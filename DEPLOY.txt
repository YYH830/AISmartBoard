  AI智能看板 · 服务器部署说明
════════════════════════════════════════════════════════════════════════

把整个文件夹传到服务器上，启动服务，就能用浏览器随时访问了。

  · 服务用 Node.js 跑，程序零依赖（不用 npm install）
  · 访问需要账号密码登录，账号密码在配置文件里设置
  · 台账数据存在「data」文件夹里，是普通 Markdown 文件

════════════════════════════════════════════════════════════════════════
  1. 最快路径（三条命令搞定）
════════════════════════════════════════════════════════════════════════

前提：服务器上已经装好 Node.js（16 以上）。在项目文件夹里依次执行：

      bash start.sh start          # 启动（会自动生成一份 .env）
      bash start.sh pass           # 看登录账号和密码
      bash start.sh status         # 确认状态

然后用浏览器打开：

      http://<服务器IP>:8765/

输入账号密码即可（默认 admin / 12345）。如果打不开，八成是端口没放行，见第 2.5 节。


════════════════════════════════════════════════════════════════════════
  2. 详细步骤
════════════════════════════════════════════════════════════════════════

2.1 上传项目
────────────────────────────────────────

把整个文件夹上传到服务器，例如放到  /opt/work-task-board 。

方式随意：宝塔面板的文件管理、scp、rsync、git 都行。例如：

      scp -r "07 个人任务工具" root@你的服务器:/opt/work-task-board

上传后确认这几个东西都在：

      app/server.js           服务程序（必需）
      app/index.html          界面（必需）
      app/login.html          登录页（必需）
      data/                   数据目录
      start.sh                启动脚本

「launchers」那个文件夹是给 Windows / Mac 本机用的，服务器上用不到，
可以不传。


2.2 安装 Node.js
────────────────────────────────────────

先确认有没有：

      node -v

有版本号（v16 以上）就跳过这步。没有的话：

  Debian / Ubuntu：

      curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
      apt install -y nodejs

  CentOS / RHEL：

      curl -fsSL https://rpm.nodesource.com/setup_20.x | bash -
      yum install -y nodejs

  或者直接用系统自带的（版本可能旧一些，但一般够用）：

      apt install -y nodejs


2.3 设置登录账号和密码
────────────────────────────────────────

第一次执行 start.sh 时会自动生成 .env 文件，默认账号密码是 admin / 12345，
可以直接登录。想改成自己的，编辑项目根目录下的 .env：

      WTK_HOST=0.0.0.0
      WTK_PORT=8765
      WTK_USER=admin
      WTK_PASS=12345

四项配置的意思：

      WTK_HOST   监听地址。0.0.0.0 = 允许外部访问（服务器部署必须是这个）
                 如果填 127.0.0.1，就只有服务器自己能访问
      WTK_PORT   监听端口。默认 8765
      WTK_USER   登录账号。默认 admin
      WTK_PASS   登录密码。留空的话服务会自动生成一个并打印在日志里

改完要重启才生效：

      bash start.sh restart

  ⚠ 安全提醒（重要）：12345 只是个让你能立刻用起来的初始密码，太简单了。
     服务一旦对外开放，网上扫端口的人很容易试出这种密码。要长期开放访问，
     请务必换成 12 位以上的复杂密码，例如：

         WTK_PASS=Xk7#mQ2pL9vN

     服务启动时如果发现你在对外监听却用的是弱密码，会在日志里打印警告。
2.4 启动服务
────────────────────────────────────────

      bash start.sh start

正常会看到类似输出：

      AI智能看板已启动
      监听地址：0.0.0.0:8765
      对外访问：http://服务器IP:8765/   （把「服务器IP」换成你服务器的实际地址）
      台账目录：/opt/work-task-board/data
      访问保护：已开启，需要密码
      登录账号：admin


2.5 放行端口（最容易漏的一步）
────────────────────────────────────────

服务跑起来了但浏览器打不开，基本都是端口没放行。要放两处：

  (1) 服务器自己的防火墙

        # 有 ufw 的（Ubuntu 常见）
        ufw allow 8765/tcp

        # 有 firewalld 的（CentOS 常见）
        firewall-cmd --permanent --add-port=8765/tcp && firewall-cmd --reload

        # 用的是 iptables
        iptables -I INPUT -p tcp --dport 8765 -j ACCEPT

  (2) 云服务商的安全组

        到云控制台（阿里云 / 腾讯云 / 华为云等）找到这台服务器的
        「安全组」或「防火墙」设置，添加入方向规则：

            协议：TCP
            端口：8765
            来源：0.0.0.0/0（或只填你自己的出口 IP，更安全）

  如果用的是宝塔面板，在「安全」页面放行 8765 端口即可。


2.6 访问
────────────────────────────────────────

浏览器打开：

      http://<服务器IP>:8765/

会先看到登录页，输入账号密码（默认 admin / 12345）就进入看板了。

登录状态会保持 30 天，期间不用重复输入。


════════════════════════════════════════════════════════════════════════
  3. 常用管理命令
════════════════════════════════════════════════════════════════════════

都在项目文件夹下执行：

      bash start.sh start       启动（后台运行，关掉终端也不影响）
      bash start.sh stop        停止
      bash start.sh restart     重启（改完 .env 后用这个）
      bash start.sh status      查看运行状态
      bash start.sh logs        实时看日志（Ctrl+C 退出）
      bash start.sh pass        查看登录账号和密码

日志文件是项目根目录下的 server.log，进程号记在 server.pid。

想在服务器重启后自动拉起服务，用 systemd（把下面内容存成
/etc/systemd/system/work-board.service）：

      [Unit]
      Description=AI智能看板
      After=network.target

      [Service]
      Type=simple
      WorkingDirectory=/opt/work-task-board
      ExecStart=/usr/bin/node /opt/work-task-board/app/server.js --no-open
      EnvironmentFile=/opt/work-task-board/.env
      Restart=on-failure
      RestartSec=5

      [Install]
      WantedBy=multi-user.target

然后：

      systemctl daemon-reload
      systemctl enable --now work-board
      systemctl status work-board

注意：用了 systemd 之后，就用 systemctl 管理服务，不要再混着用 start.sh，
否则可能启动出两个实例（第二个会被自动识别并退出，但没必要）。


════════════════════════════════════════════════════════════════════════
  4. 方式 B：用 Docker 部署
════════════════════════════════════════════════════════════════════════

如果你的服务器上跑的是容器化环境（青龙面板、1Panel、宝塔 Docker 等），
用 Docker 部署更省事。项目里已经准备好了 Dockerfile 和 docker-compose.yml。

4.1 用 docker compose（推荐）
────────────────────────────────────────

先把 docker-compose.yml 里的 WTK_USER、WTK_PASS 改成你自己的账号密码，然后：

      docker compose up -d

看日志：

      docker compose logs -f

停止：

      docker compose down

4.2 用 docker 命令
────────────────────────────────────────

      docker build -t work-task-board .

      docker run -d \
        --name work-board \
        --restart unless-stopped \
        -p 8765:8765 \
        -e WTK_USER=admin -e WTK_PASS=你的密码 \
        -v /opt/work-task-board/data:/app/台账 \
        work-task-board

  ⚠ 一定要挂载 -v 到宿主机目录，否则容器重建后台账数据会丢。

4.3 关于青龙面板等定时任务类面板
────────────────────────────────────────

青龙面板的任务是"跑一次就结束"的脚本，而看板是一个需要一直活着的
HTTP 服务，两者定位不同。如果只有青龙面板可用，有两种做法：

  (1) 推荐：用青龙面板的「Docker 管理」功能，按上面 4.2 的方式跑一个
      长期容器（青龙本身就跑在 Docker 里，一般有现成的入口）。

  (2) 退一步：在青龙里建一个任务，命令写：

          cd /path/to/项目 && bash start.sh start

      并把它设成"每天执行一次"。start.sh 会先检查服务是否已在运行，
      已运行就直接退出，不会重复启动。这种方式能保证服务掉线后最迟
      一天内被拉起来，但不算实时守护。

      注意：青龙的容器和宿主机之间需要把 8765 端口映射出来，否则外面
      访问不到，具体在青龙容器的端口映射里加一条 8765:8765。

  5. 方式 C：配域名和 HTTPS
════════════════════════════════════════════════════════════════════════

如果想让地址好看一点（比如 http://task.你的域名.com），或者想用 HTTPS，
就再加一层 nginx 反向代理。

nginx 配置示例：

      server {
          listen 80;
          server_name task.你的域名.com;

          location / {
              proxy_pass http://127.0.0.1:8765;
              proxy_set_header Host $host;
              proxy_set_header X-Real-IP $remote_addr;
              proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
              proxy_set_header X-Forwarded-Proto $scheme;
          }
      }

配好之后把 .env 里的 WTK_HOST 改成 127.0.0.1（只让 nginx 访问，
服务本身不直接暴露到公网），然后 bash start.sh restart。

想上 HTTPS，最简单的是用宝塔面板申请免费证书，或者用 certbot：

      apt install -y certbot python3-certbot-nginx
      certbot --nginx -d task.你的域名.com

  ⚠ 如果用国内服务器 + 自己的域名，域名需要先完成 ICP 备案才能正常访问。

  6. 安全须知（重要）
════════════════════════════════════════════════════════════════════════

  · 一定要改掉默认密码。这是你的个人台账，公网上任何知道地址的人都能读写。
    admin / 12345 只是初始值，上线后第一件事就该换掉。

  · 账号不要用 admin。这是所有扫描器第一个试的用户名，改成别的能挡掉大量
    自动化的撞库尝试。

  · 建议限制来源。云安全组的来源别图省事填 0.0.0.0/0，能填你自己的
    常用出口 IP 就填上（家、公司）。不方便的话至少设个强密码。

  · 密码别太短。服务对登录失败做了延迟处理，但弱密码在网上被撞开
    只是时间问题。十几个字符、含大小写和数字比较稳。

  · 登录失败会统一提示"账号或密码不正确"。不区分是哪个错，免得帮人确认账号是否存在。

  · 登录状态存在浏览器 Cookie 里，标记了 HttpOnly —— 网页脚本读不到，
    就算看板页面有 XSS 漏洞也偷不走。有效期 30 天。

  · 想临时停用看板，执行 bash start.sh stop 即可，数据文件不受影响。

  · 数据备份很简单：把「data」文件夹复制走就行。所有台账都是纯文本
    Markdown 文件，用记事本就能打开看。


════════════════════════════════════════════════════════════════════════
  7. 常见问题
════════════════════════════════════════════════════════════════════════

启动报错「未检测到 Node.js」
────────────────────────────────────────

按第 2.2 节安装。装完执行 node -v 确认有版本号再重试。

浏览器打不开，一直转圈
────────────────────────────────────────

按顺序排查：

  (1) 服务在不在跑：       bash start.sh status
  (2) 服务器本机通不通：   curl http://127.0.0.1:8765/api/ping
      返回 {"ok":true,...} 说明服务正常，问题在网络上
  (3) 端口放行了吗：       见第 2.5 节（防火墙 + 云安全组两处都要）
  (4) 从外面测端口通不通： telnet 你的服务器IP 8765

提示「检测到任务看板服务已在运行」
────────────────────────────────────────

说明服务已经起着了，不用重复启动。直接访问看板即可。
想重启就先 bash start.sh stop，再 start。

忘记密码了
────────────────────────────────────────

      bash start.sh pass        # 直接看当前账号和密码

或者编辑 .env 改掉 WTK_USER / WTK_PASS，然后 bash start.sh restart。

页面提示「unauthorized」或不停跳回登录页
────────────────────────────────────────

登录状态失效了（改了账号密码，或超过 30 天）。刷新页面重新登录即可。
如果密码没改却一直反复要求登录，检查浏览器是不是禁用了 Cookie。

改了 .env 但不生效
────────────────────────────────────────

配置是启动时读一次的，改完要重启：

      bash start.sh restart

端口 8765 被占用
────────────────────────────────────────

服务会自动往后试 8766、8767…… 实际端口记在 server.log 里。
也可以直接换个端口：改 .env 里的 WTK_PORT。

台账数据在哪？
────────────────────────────────────────

项目文件夹下的「data」子目录，都是 .md 文件。
Docker 部署的话，看你 -v 挂载到了宿主机哪个目录。

多个设备同时用会冲突吗？
────────────────────────────────────────

不会。看板会定时检查文件是否被外部修改，发现变化就自动同步。
但请避免在两台设备上同时编辑同一个台账，否则后保存的会覆盖先保存的。

想升级程序怎么办？
────────────────────────────────────────

直接用新版覆盖「app」文件夹，然后 bash start.sh restart。
「data」文件夹别动，数据都在里面。
